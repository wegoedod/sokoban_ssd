# AstroDeck (3D 소코반, 기본 게임)

요구사항 명세서 v1.0 중 기본 게임과 **포탈·순서 목표 기믹**을 구현했다. 게임 로직은 **완전한 3차원 격자**다: 플레이어와 상자가 x, y, z 6방향으로 움직인다. Java 17+ / Swing(Graphics2D), 외부 라이브러리 없음.

## 실행

| 목적 | Windows | bash |
|---|---|---|
| 컴파일 | `build.bat` | `./build.sh` |
| 실행 | `run.bat` | `./run.sh` |
| 단위 테스트 | – | `./test.sh` |
| 레벨 검증·최적해 기록 | `java -cp out sokoban.tool.LevelTool` | 〃 |

저장 파일은 `~/.sokoban25d/save.properties` (`-Dsokoban.save=경로`로 변경). 레벨·설정 위치는 `-Dsokoban.home=폴더`(기본 현재 폴더).

## 조작

| 키 | 동작 |
|---|---|
| `W` `A` `S` `D` | 평면 이동 (화면 기준: W 오른쪽 위, D 오른쪽 아래, S 왼쪽 아래, A 왼쪽 위) |
| `↑` / `↓` | z축 위(+z) / 아래(−z) 이동. 2D(한 층) 레벨에서는 동작하지 않는다 |
| `←` / `→` | 시점 회전 (45°씩, 8방향). 2D(한 층) 레벨에서는 고정 |
| `Z` / `Y` | 되돌리기 / 다시 하기 |
| `R` | 리셋 |
| `Esc` | 일시정지 |
| `V` | 시점 초기화 |
| `Tab` | 층 강조 (현재 층만 선명하게: 위층은 많이, 아래층은 조금 흐리게. 켜지면 오른쪽 위에 표시) |

마우스는 메뉴 선택·호버에만 쓴다(시점은 마우스로 돌리지 않는다). 한글 입력기가 켜져 있어도
`KeyNormalizer`가 자모를 영문 키로 보정해 W/A/S/D와 Z/Y/R/V가 그대로 동작한다.

**막힌 입력**: 이동이 막히면(이동 횟수에는 포함되지 않는다) 막은 칸(벽·격자 끝·상자 뒤의 벽이나 상자·구멍·잠긴 목표)이
빨갛게 두 번 번쩍이고 화면 가운데에 이유가 한 줄로 나온다. 막은 칸은 `Engine.whyBlocked`가 알려 주며,
`step()`과 어긋나지 않는지 단위 테스트가 모든 출고 레벨에서 검사한다. 막히는 규칙이 늘면 `whyBlocked`에도 사유를 추가한다.

**레벨 선택(우주 지도)**: 레벨은 목적지(행성·웜홀·우주정거장)다. 레벨 1은 지구이고, 목적지들이 지그재그 길로 이어진다. 로켓이 선택한 목적지까지 한 칸씩 뛰어서 이동한다(`←` `→`, `Home`/`End`). `Enter` 또는 목적지 클릭(고른 목적지를 한 번 더 클릭)·출발 버튼(행성 `착륙`, 웜홀 `진입`, 정거장 `도킹`)으로 레벨을 시작한다. 처음 열 때만 지구에서 출발해 선택된 레벨까지 날아가고, 레벨을 풀고 돌아올 때는 바로 그 목적지에 서 있다. 잠긴 목적지는 자물쇠로 표시한다. 아래 정보 패널에는 레벨 이름, 무대, 쓰인 기믹(구멍·포탈·자기장·순서 목표)이 나온다. 목적지 이름과 그림은 레벨의 테마별로 차례대로 정해진다(아래 [무대(테마)](#무대테마)).

**플레이 화면 무대**: 배경과 벽·격자 색이 레벨 테마를 따른다. 행성은 별이 뜬 하늘 아래 그 행성의 지평선(벽도 행성 색이 섞인 암석색), 웜홀은 천천히 도는 보랏빛 소용돌이, 우주정거장은 금속 선체 패널·관측창·깜빡이는 표시등·경고 띠(벽은 강철색)다. HUD 둘째 줄에 목적지 이름과 무대가 나온다. 구현은 `WorldStyle`(배경·팔레트)과 `IsoRenderer.setPalette`.

**설정(Esc) · 테스트 코드**: 어느 화면에서든 `Esc`로 설정 창을 연다. 설정 창의 `테스트 코드` 항목에서 `123456`을 입력하고 `Enter`/`확인`을 누르면 **출고된 모든 레벨(33개)이 최적 기록(★★★·1000점·최적 이동)으로 클리어 처리**되어 레벨 선택의 별과 행성 해금이 바로 채워진다(시연·QA용). 숫자 입력·`Backspace`·`Enter` 확인·`Esc` 취소로 조작하고, 마우스로도 입력판을 열고 취소/확인을 누를 수 있다. 다른 코드는 "올바르지 않은 코드입니다"만 띄우고 기록을 건드리지 않는다.

**카메라**: 기본은 아이소메트릭 3D 시점(yaw 0°, pitch 30°)이다. `←` `→` 로 45°씩 돌린다(8방향).
`V` 시점 초기화, `Tab` 층 강조.
이동 키는 항상 **화면 기준**이다: 카메라를 돌려도 키가 가리키는 화면 쪽으로 간다.
- 90° 배수 시점(0°·90°·180°·270°)에서는 키가 가리키는 화면 대각선과 격자 방향이 정확히 일치한다.
- 45° 반 걸음 시점(45°·135°·225°·315°)에서는 격자 축이 화면 축과 나란해져 W/A/S/D가 화면
  위/왼쪽/아래/오른쪽 방향으로 그대로 움직인다. 네 키는 어떤 시점에서도 서로 다른 방향을 가리킨다.

**2D 탑뷰 → 3D 확장 연출**
- 한 층짜리 레벨(1~3단계)은 **2D 탑뷰**(yaw −45°, pitch 90°)로 고정된다. 기울기가 90°라 z축이 화면에서
  사라지고 yaw 가 격자 축을 화면 축과 맞춰 주므로, 격자가 2D 소코반처럼 반듯한 정사각 타일로 그려진다.
  이 단계에서는 시점 회전(`←` `→`)과 z축 이동(`↑` `↓`)이 동작하지 않는다(W/A/S/D는 화면 위/왼쪽/아래/오른쪽).
- **4단계(첫 3D 레벨)에 들어가면** 화면이 탑뷰에서 시작해 0.9초 동안 부드럽게 기울고 돌아가며
  3D 시점(pitch 30°, yaw 0°)으로 확장된다. 다음 레벨로 넘어갈 때와 레벨 선택에서 4단계를 고를 때 모두 나온다.
- 5단계부터는 처음부터 3D 시점으로 시작한다(`V` 는 언제나 3D 기본 시점으로 돌아온다).

## 3D 규칙 (명세서와 달라진 점)

- 중력·바닥이 없다. 모든 빈 칸은 공중이고 플레이어도 상자도 공중에 머문다. 격자 밖은 고체다.
- 플레이어가 z축으로 자유롭게 이동한다 (명세 FR-1.7 "층 고정"을 폐기). 계단·리프트 기믹이 필요 없어진다 → 기믹 목록 재검토 필요.
- 상자는 플레이어가 미는 방향 6방향 어디로든 한 칸씩 밀린다. 뒤가 벽·상자·격자 밖이면 막힌다(연쇄 없음).
- 구멍은 3D 셀이다. 어느 방향으로 밀어 넣어도 상자와 구멍이 함께 소멸한다.
- 렌더링: 아이소메트릭 투영 + 바닥 격자·바닥 그림자·플레이어 층 평면으로 높이를 읽는다. 플레이어는 정사면체, 벽은 반투명 큐브.

## 구조

```
src/sokoban/
  core/    Direction, TileType, Level, GameState(불변), Engine(순수 규칙), Session(되돌리기), Scoring
  level/   LevelParser, LevelRepository, Difficulty
  solver/  Solver (BFS, Engine 재사용)
  config/  GameConfig
  save/    SaveStore
  ui/      App, 화면들, IsoRenderer(회전 투영), Camera(yaw/pitch, 키 매핑)
  tool/    LevelTool
```

`core`·`level`·`solver`는 Swing에 의존하지 않는다(NFR-1). 되돌리기는 불변 `GameState` 스냅샷 스택이다(FR-3.7).

### 기믹 추가 지점

`Engine.step`의 턴 순서는 `플레이어 이동 → 밀기 → 포탈 전송 → 구멍 채움 → 클리어 판정`이다.
새 기믹은 이 사이에 단계로 끼운다(잠긴 목표 차단은 이동·밀기 전에, 순서 목표 진행도는 상자 배치에서 계산).
블록 속성(중력·방향 제한·연쇄)은 `GameState`의 블록에 속성 객체를 붙이는 방식으로 확장한다(NFR-4).
`Difficulty`·`GameConfig`는 기믹 가중치를 반영하며, 현재 출고 레벨에는 포탈 한 쌍이 있다.

### 순서 목표 기믹

목표 칸에 숫자(`1`~`9`)를 적으면 그 목표는 **순서 목표**가 된다. 지형은 그대로 목표(`GOAL`)이고 번호만 따로 붙는다.
1번부터 연속으로 상자가 올라가 있는 수를 k라 하면 **활성 번호는 k+1뿐**이다. 즉 1번 목표에 상자가 없으면 1번만 열려 있고
2·3번은 잠겨 있다. **1번 목표에 상자를 넣는 순간 2번이 열리고**, 2번을 채우면 3번이 열린다.
잠긴 목표 칸에는 플레이어가 들어가지 못하고(`LOCKED_GOAL`) 상자도 밀어 넣을 수 없다
(`PUSH_LOCKED_GOAL`, 포탈 출구에서 미는 경우 포함). 번호 없는 목표(`.`)는 일반 목표로 항상 활성이다.
클리어는 일반 목표와 순서 목표 **모두**에 상자가 올라가야 성립한다.

잠금은 `GameState`에 저장하지 않고 **상자 배치에서 순수하게 계산**한다(`filledSequenceGoals`, `unlockedGoalOrder`, `goalUnlocked`).
따라서 되돌리기(Z)·다시 하기(Y)·리셋과 솔버가 잠금 상태까지 저절로 함께 복원하고, 상태 비교·해시도 상자 배치만 보면 된다.
이미 채운 목표에서 상자를 빼면 뒷번호 목표가 다시 잠기므로(그 위 상자는 되돌리기·리셋으로만 회복) 순서를 지켜야 한다.
화면에서는 활성 목표를 금색, 상자가 올라간 목표를 초록, 잠긴 목표를 어두운 회색 테두리와 자물쇠로 그리고
목표마다 번호 패를 띄우며, HUD 왼쪽에 `순서 목표 1 / 3` 진행도와 막힘 안내
(`2번 목표는 아직 잠겨 지나갈 수 없습니다 · 먼저 1번 목표에 상자를 넣으세요`)를 보여 준다.

출고 레벨 32(잠긴 길목)은 이 기믹으로 **길목 막기**를 만든 예시다. 두 방을 가르는 벽(`x=4`)에
문이 하나뿐인데 그 칸이 `2번 목표`다. 잠겨 있는 동안에는 벽을 넘어가지 못해 오른쪽 방에
들어갈 수 없고, `1번 목표`(바닥 구멍)에 상자를 넣는 순간 문이 열린다. 오른쪽 방의 목표를 모두
채우고 돌아온 뒤 문 칸에 상자를 밀어 넣으면(문도 목표라 상자가 올라가야 한다) 클리어된다.
문에 상자가 들어가면 그쪽 길이 막히므로, 방을 비운 뒤 마지막에 문을 채우는 순서가 핵심이다.

## 무대(테마)와 캠페인 구성

레벨마다 무대가 있고 기믹에 맞춘다. 레벨 파일의 `theme:`으로 적고, 없으면 기믹으로 고른다(`LevelTheme.infer`):
자기장 장치·스위치·순서 목표(잠긴 문)가 있으면 **우주정거장**, 포탈만 있으면 **웜홀**, 기믹이 없거나 구멍(크레이터)뿐이면 **행성**이다.
테스트(`shippedLevelThemes`)가 출고 레벨의 `theme` 값이 기믹과 맞는지 검사한다. 무대는 규칙에 영향을 주지 않는다.

지도 목적지는 테마별로 앞에서부터 이름을 붙인다(`PlanetArt.destinations`). 첫 행성 레벨은 지구, 첫 웜홀은 "웜홀", 첫 정거장은 "안드로메다 정거장"이다.
목록을 넘으면 "미지의 행성 N", "미지의 웜홀 N", "정거장 N호"를 만든다.

| 구역 | 단계 | 무대 | 레벨 (최적 수) | 배우는 것 |
|---|---|---|---|---|
| 태양계 | 1–10 | 행성 (지구 → 해왕성) | 한 방향(2) · 꺾어 밀기(5) · 두 개의 짐(4) · 위로(2) · 아래로(2) · 계단식(5) · 모서리 돌기(7) · 기둥 옆(10) · 첫 구멍(8) · 우물(14) | 2D 밀기 → 3D 이동 → 구멍 |
| 웜홀 지대 | 11–14 | 웜홀 | 웜홀 입문(4) · 상자 전송(7) · 두 개의 문(17) · 크레이터 웜홀(8) | 포탈: 플레이어 전송 → 상자 전송·따라 들어가 밀기 → 양방향 → 포탈+구멍 |
| 외행성 | 15–18 | 행성 (명왕성 → 마케마케) | 둘씩 둘(13) · 구멍과 목표(17) · 엇갈림(18) · 깊은 구멍(21) | 여러 상자·구멍 응용 |
| 우주정거장 | 19–24 | 우주정거장 | 안드로메다 관문(6) · 전원 차단(14) · 순서대로(13) · 자석 열쇠(7) · 자기 함정(8) · 자력 중계(9) | 자기장 ON → 붙은 상자는 OFF 후 이동 → 순서 목표 → 기믹 섞기(자기장+순서, 자기장+구멍, 자기장+포탈) |
| 심우주 | 25–33 | 행성·웜홀·정거장 | 세 개의 짐(22) · 다락과 지하(22) · 잠긴 웜홀(21) · 막다른 방(27) · 구멍 열쇠(29) · 차원의 문(33) · 쌍둥이 포탈(35) · 잠긴 길목(35) · **최종 관문(19)** | 종합. 최종 관문은 순서 목표·자기장·스위치·포탈을 모두 쓴다 |

- **전원 차단**: 철 상자가 손이 닿지 않는 벽 틈에 있다. 스위치로 자기장을 켜서 끌어오고, 붙은 상자는 밀리지 않으므로 스위치를 다시 밟아 끈 뒤 위층에서 아래로 밀어 목표에 넣는다.
- **자석 열쇠**: 자기장 바로 앞 칸이 잠긴 `2번 목표`라 자기장이 막혀 있다. 아래층 `1번 목표`에 상자를 넣는 순간 2번이 열리면서 철 상자가 날아와 2번에 붙고, 그다음 3번이 열린다.
- **크레이터 웜홀** (포탈+구멍): 포탈 출구 바로 앞이 구멍이다. 상자를 포탈로 보내고 따라 들어가면 그 상자가 구멍을 메워 다리가 되고, 건너편 상자를 목표로 민다.
- **자기 함정** (자기장+구멍): 자기장 선 위에 구멍이 있어, 먼저 켜면 철 상자가 구멍에 빠져 막힌다. 스위치가 길목에 있으므로 위층으로 돌아가 일반 상자로 구멍부터 메운 뒤 켠다.
- **자력 중계** (자기장 두 개+포탈): 1번 자기장이 철 상자를 포탈로 끌어 보내고, 위층 2번 자기장이 받아 목표로 끌어온다. 2번 선을 가린 일반 상자를 아래 목표로 치워야 하며, 그 상자를 자기장 앞 목표에 밀어 넣으면 막힌다.
- **잠긴 웜홀** (순서 목표+포탈): 1·3번 목표는 위층(포탈로만 감), 2번은 아래층에 있어 포탈 두 쌍으로 오가며 순서대로 채운다.
- **구멍 열쇠** (순서 목표+구멍): 2·3번 목표가 구멍 너머 외길 끝에 있다. 구멍을 메우고, 상자를 2번을 지나 3번까지 밀어 둔 뒤 다음 상자로 2번을 채운다. 상자 4개(목표 3 + 구멍 1)가 모두 필요하므로 위층 상자도 아래로 내려 써야 한다.
- **최종 관문**: 일반 상자가 자기장 선을 가리고 있어 먼저 1번 목표로 치운다. 철 상자를 끌어온 뒤 스위치로 되돌아가려면 위층 우회로를 써야 하고, 전원을 끈 철 상자를 포탈로 밀어 보낸 뒤 따라 들어가 2번 목표에 밀어 넣는다.

레벨 파일 번호(`levelNN.txt`, `id: LNN`)는 캠페인 순서와 같다. 바깥 테두리는 격자 밖(고체)과 규칙이 같으므로 `#`로 두르지 않아도 된다(두르면 3D 화면에서 게임판을 가린다).

## 레벨 파일 (`levels/*.txt`)

```
id: L01
name: 첫 걸음
optimalMoves: 2      # LevelTool이 기록
solution: RR         # LevelTool이 기록
layer 0
######
#@$-.#
######
```

`#`벽 `-`(또는 공백)빈 공간 `.`목표 `O`구멍 `A`/`B`포탈 쌍 `$`블록 `*`목표 위 블록 `@`플레이어 `+`목표 위 플레이어 `1`~`9`순서 목표(번호가 붙은 목표). `layer 0`이 맨 아래 층. 풀이 기호는 `U R D L`(평면) `T`(위) `B`(아래).
선택 메타: `star3`, `star2`(별 비율 덮어쓰기), `theme`(`planet`·`wormhole`·`station`, 무대. 없으면 기믹으로 고른다). 새 레벨은 파일만 추가하고 `LevelTool`을 돌리면 풀이 가능 여부 검증과 `optimalMoves` 기록이 된다.
`optimalMoves`가 없는 레벨은 로드되지 않는다(FR-5.9). 레벨 목록은 난이도 D 오름차순이다.

## 가정한 것

- 명세서는 레벨 파일 형식을 "텍스트 또는 JSON"으로 열어 두었다 → 텍스트로 정했다.
- 블록은 구별하지 않는다(목표의 종류 일치 불필요, 결정 #5).
- 레벨 수는 33개다 (2D 레벨 3개 + 3D 레벨 30개). 명세의 36개는 기믹 포함 목표다.
- 1~3단계는 `layer 0` 한 층짜리 2D 레벨이고, 4단계부터 여러 층을 쓰는 3D 레벨이다. 레벨 목록은 난이도 D 증가 순서라
  이 순서가 그대로 플레이 순서가 된다(2D 레벨의 D가 가장 낮다).
